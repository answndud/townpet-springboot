## Summary

이메일 실패 시 사용자 무음 상태, Modulith 미완료 이벤트 재시작 미복구, 알림 중복 저장, 오류 후 재시도 UX 부재를 순서대로 해결했다. 모든 변경은 기존 동시성 설계(row lock, atomic upsert, optimistic version)를 유지하며, 재시도 안전성을 먼저 확인한 뒤 적용했다.

## 변경 내역

### P1 — 이메일 실패 사용자 피드백

- **문제**: 인증·재설정 메일 발송이 비동기 리스너에서 실패해도 API는 200을 반환하고 사용자는 메일 미수신 원인을 알 수 없었다.
- **해결**: `VerifyEmailPage`, `PasswordResetPage`의 성공 안내에 "스팸함 확인 또는 몇 분 뒤 재요청" 가이드 추가.
- **효과**: SMTP 장애 시 사용자가 스스로 복구 경로를 찾을 수 있고 운영 문의가 감소한다. 백엔드 응답 계약은 변경하지 않았다.

### P2 — 이벤트 재시작 복구

- **문제**: 프로세스 크래시 시 PostgreSQL에 남은 미완료 event publication이 재시작 후 자동 재처리되지 않았다.
- **해결**: `spring.modulith.events.republish-outstanding-events-on-restart=true` 설정 추가 (`application.yml`).
- **효과**: 배포 중단·크래시 후 알림 등 후속 처리가 자동으로 이어진다. Event Publication Registry의 PostgreSQL 영속성이 이미 있었으므로 추가 인프라 없이 설정만으로 활성화됐다.

### P3 — 알림 중복 방지 (idempotency)

- **문제**: `NotificationEventHandler`가 Modulith 재시도 시 동일 이벤트를 여러 번 처리해 중복 알림 row가 생성될 수 있었다.
- **해결**:
  - `NotificationEvent`에 `eventId` 필드 추가 — 게시자가 이벤트별 고유 식별자를 담음.
  - V066 migration: notification 테이블에 `event_id UUID NOT NULL UNIQUE` 컬럼 추가 (기존 행은 `gen_random_uuid()`로 backfill).
  - 핸들러에서 `DataIntegrityViolationException` catch → 재처리된 publication은 조용히 스킵.
- **효과**: at-least-once 전달 + DB unique constraint = effectively-once 알림. 앱 레벨 flag 없이 DB 불변식으로 보장한다.

### P4 — 오류 후 재시도 UX

- **문제**: Gathering 생성 실패 시 일반 오류 메시지만 표시되어 재시도 가능 여부가 불명확했다.
- **해결**: 오류 메시지에 `aria-live="polite"` 적용, 폼 값 유지를 명확히 하여 재제출이 안전함을 표현.
- **효과**: 네트워크 오류 후 사용자가 입력 손실 없이 즉시 재시도할 수 있다.

## 한계와 후속 과제

- V066 migration이 운영에 처음 적용된다. Flyway가 append-only로 실행하며 기존 데이터가 소량(현재 알림 0행 근접)이라 backfill 위험은 낮다.
- 이메일 발송 자체의 재시도 간격(50/100ms)은 그대로 두었다. Modulith registry의 재시도가 실질 안전망이므로 리스너 내부 sleep 조정은 실측 요구가 생길 때까지 유보한다.
