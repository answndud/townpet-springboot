## 1. 공개 write와 검색 abuse

### 적용

- `GuestPublicationController`와 `GuestCommentController`에 IP별·guest별 시간당 제한을 적용했다. 비회원 생성량은 일일 quota가 아니라 시간당 정책이다.
- 게시글 수정·삭제에도 IP/guest mutation 제한을 적용했다.
- `SearchEventController`에 IP별 분당 및 전역 시간당 ingress 제한을 적용했다.
- `SearchEventCleanup`이 보존 기간을 지난 `search_event`를 주기적으로 삭제한다.
- 제한 counter는 PostgreSQL `security_rate_limit_window`의 원자적 upsert로 공유된다. 따라서 backend 인스턴스 재시작이나 수평 확장으로 제한을 우회하지 않는다.

## 2. Presigned upload 안전 한계

### 적용

- presigned POST에 object key, MIME type, 정확한 `Content-Length` 조건을 서명한다.
- 이미지 finalize 시 MIME, byte size, 이미지 header의 width/height, 총 pixel 수를 서버에서 검사한다.
- 최대 해상도는 8000×8000, 총 pixel 한도는 32,000,000으로 제한한다.
- header가 유효하지 않거나 제한을 넘으면 finalize를 거부하고 object를 삭제한다.
- 기존 사용자별 upload 횟수·저장량 quota와 동시 요청 row lock을 유지한다.

## 4. Moderator MFA

### 적용

- moderator TOTP enrollment, confirm, verification, one-time recovery code를 구현했다.
- TOTP secret은 기존 account token 암호화 경계를 사용해 저장한다.
- MFA 미완료 moderator의 admin/operations API 접근은 서버 filter가 `403`으로 차단한다.
- 로그인 세션에 MFA 완료 상태를 기록하고, password-only moderator 세션은 보호 API를 사용할 수 없다.
- MFA 시작·확인·검증·recovery endpoint에 IP/member rate limit을 적용했다.
- enrollment·enabled·verified·recovery 사용 이벤트를 audit action으로 기록한다.

## 7. 잔여 위험과 판정

이 문서의 구현 항목만으로 High/Medium 위험이 자동으로 0이 되는 것은 아니다. 코드상 계획된 경계는 구현했지만, DNS·메일 전달·실패 알림·최신 배포·GitHub Actions 결과가 확인되기 전에는 운영 출시 판정을 `CONDITIONAL PASS` 이상으로 올리지 않는다.

다음 운영 증거가 추가되면 해당 항목을 재판정한다.

1. SPF/DKIM/DMARC와 provider verified 상태
2. 실제 verification/password-reset 수신 및 링크 host/scheme
3. 최신 backup script 배포 후 실패 webhook 수신
4. 최신 commit의 GitHub security workflow 실행 결과
