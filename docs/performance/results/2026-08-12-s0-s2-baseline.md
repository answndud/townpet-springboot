# S0~S2 HTTP 기준선 - baseline

## Summary

- 실행일: 2026-08-12
- 상태: `baseline`
- 환경: 로컬 macOS + Docker Desktop, Spring Boot perf profile `8081`, PostgreSQL 18.4 전용 DB `54331`, k6 `0.52.0`
- 주의: 로컬 1 VU 결과이며 운영 SLA가 아니다. 이번 실행부터 k6 summary에 p99를 포함했다.

## Results

| scenario | fixture | VU/stage | requests | throughput | p50 | p95 | p99 | unexpected HTTP error |
|---|---:|---|---:|---:|---:|---:|---:|---:|

반복 원본은 각각 다음 run directory에 있다.

- S0: `20260812T144052Z`, `20260812T144128Z`, `20260812T144205Z`
- S1: `20260812T144245Z`, `20260812T144507Z`, `20260812T144727Z`
- S2: `20260812T144954Z`, `20260812T145214Z`, `20260812T145434Z`

표의 p50/p95/p99/처리량은 세 실행의 중앙값이다. S0 p95/p99는 BCrypt 로그인과 cold 요청이 포함된 여정 지표라 S1/S2와 직접 비교하지 않는다.

S0는 health·public feed·CSRF·login·viewer-shell을 한 사용자 여정으로 실행하므로 BCrypt 로그인과 cold/warm 요청이 섞여 p95가 높다. S1/S2는 로그인 후 읽기 요청을 측정한다.

## Scenario checks

- S0: health, feed, CSRF, login, member viewer-shell checks 100% 통과
- S1: public feed, popular feed, local resources checks 100% 통과
- S2: member profile, notifications, unread count, bookmarks, viewer feed checks 100% 통과
- 초기 member-read harness는 k6 cookie jar에서 `SESSION`을 명시적으로 전달하지 않아 401이 발생했다. 명시적 `SESSION`·`XSRF-TOKEN` cookie 전달로 수정한 뒤 smoke와 baseline을 다시 실행했으며, 401 실행은 결과로 채택하지 않았다.

## Reproduction

```bash
./scripts/performance/prepare.sh small
./scripts/performance/start.sh
./scripts/performance/seed.sh small
./scripts/performance/run.sh --scenario smoke --profile smoke
./scripts/performance/run.sh --scenario public-read --profile baseline
./scripts/performance/run.sh --scenario member-read --profile baseline
```

원본 k6 JSON과 console output은 저장소에 커밋하지 않고 `build/performance/runs/<run-id>/`에서 재생성한다.
