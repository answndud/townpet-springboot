# 로컬 개발 워크플로

## 사전 조건

- JDK 25
- Docker Desktop 또는 호환 Docker daemon
- 저장소의 Gradle Wrapper
- frontend 개발 시 Node.js와 Corepack/pnpm
- Git

production secret이나 실제 사용자 데이터를 로컬에 복사하지 않는다.

## Backend만 확인

```bash
./gradlew clean check
```

특정 범위만 빠르게 확인하려면 다음을 사용한다.

```bash
./gradlew test
./gradlew integrationTest
./gradlew modulithTest
./gradlew migrationTest
./gradlew parityInventoryTest
./gradlew performanceTest
```

동시에 여러 Testcontainers를 띄우지 않도록 Gradle test fork는 1개로 고정되어
있다. 작은 변경마다 모든 task를 반복하지 말고 변경 경계에 가장 가까운 task부터
실행한다.

## Docker local stack

```bash
docker compose -f deploy/compose/local.yml up -d postgres minio
SPRING_PROFILES_ACTIVE=local \
TOWNPET_DB_URL=jdbc:postgresql://localhost:54329/townpet \
TOWNPET_DB_USERNAME=townpet_app \
TOWNPET_DB_PASSWORD=townpet_local_dev \
./gradlew bootRun
```

로컬 stack은 PostgreSQL/PostGIS, MinIO, backend를 포함한다. backend health가
`UP`이 된 뒤 frontend를 별도로 실행한다. 종료는 `docker compose ... down`을
사용하며 데이터를 초기화할 때만 `-v`를 명시한다.

## Frontend

```bash
cd frontend
corepack pnpm install --frozen-lockfile
corepack pnpm typecheck
corepack pnpm test
corepack pnpm dev
```

Vite dev server의 API proxy 설정은 frontend 설정을 따른다. CORS를 임시로 열어
문제를 숨기지 말고 browser network와 backend log의 실제 status를 확인한다.

## Demo fixture

로컬 합성 데이터는 다음 script 중 하나를 사용한다.

```bash
./scripts/seed-local-demo.sh
./scripts/seed-local-community-demo.sh
```

fixture는 합성 계정·콘텐츠만 사용해야 한다. reset script가 있는 환경에서는
`reset-demo-data.sh`를 실행하기 전에 필요한 로그와 DB backup을 보관한다.
